# Project Overview — Sift（本地优先的下载文件夹持续整理 Agent）

> 本文档是给 coding agent 的项目规格与约束。请严格按「产品原则」和「非目标」执行，不要自行扩展功能范围。遇到与本文档冲突的直觉，以本文档为准。

---

## 1. 一句话定位

**Sift 是一个本地优先的桌面应用，把用户的下载文件夹从"一次性整理"变成"持续可理解、可检索、可审计"的整理系统。**

它不是"AI 自动移动文件工具"。默认状态下 **不移动任何文件**；它先建立语义索引和虚拟视图，物理归档是用户显式发起的可选动作，且全程可审计、可撤销。

**AI 能力由用户自带的 API Key 提供。** 应用本身不代理、不转售、不内置任何模型额度。未配置 Key 时，索引、虚拟视图、手动标签、归档、账本等核心功能完全可用，仅"自动生成建议"不可用。

---

## 2. 目标用户与核心痛点

- **用户**：下载文件夹长期混乱、但不愿意花时间手动整理、也不信任"AI 自动删/移文件"的普通用户与知识工作者。
- **痛点 A**：整理一次，三天后新文件涌入，又乱了。一次性整理工具无法持续。
- **痛点 B**：AI 整理工具会"强行分类"，拿不准的文件也硬塞，用户不敢用。
- **痛点 C**：物理移动不可逆，误移动代价高，用户对 AI 碰文件系统有心理障碍。
- **痛点 D**：整理完说不清"AI 到底动了什么"，无法复盘。

产品必须同时回应 A/B/C/D 四个痛点，缺一不可。

---

## 3. 产品原则（不可妥协）

1. **默认不动文件。** 首次使用只做只读索引，不产生任何 `rename / move / delete` 操作。
2. **模型没有文件系统执行权。** LLM 只能输出结构化"整理计划"（JSON），实际文件操作由主进程中的确定性执行器完成。模型无法直接调用 `fs`。
3. **不确定性是合法输出。** 低置信度文件必须进入"待定箱"，不允许硬猜分类。
4. **所有变更可审计、可跨会话撤销。** 每一次物理文件操作都写入 append-only 账本。
5. **数据库零配置，密钥由用户自备。** SQLite 在首次启动时自动创建，用户不需要安装或配置任何数据库服务；AI Provider 的 API Key 由用户在自己的 Provider 后台获取并填入，应用不内置、不代理、不转售任何 Key。
6. **密钥永不进入渲染层。** 用户填入的 API Key 经 Electron `safeStorage` 加密后存放于主进程侧，渲染层只能看到"已配置 / 未配置"的状态，永远拿不到明文。所有模型调用从主进程（或 `utilityProcess`）发起，渲染层通过 IPC 请求。
7. **敏感数据不出设备。** 文件内容索引、向量、操作日志全部本地存储；只有用户触发分析时必要的文本片段才会发给用户自己配置的 Provider。

## 4. 核心功能模块

### M1 — 增量监听 + 纠正反馈学习（差异化方向 1）
- 监听用户授权的下载目录，新文件落地后进入"待整理队列"，而不是等用户手动扫描。
- 对每个文件生成分类建议，记录 **用户选择**（接受 / 改到别的分类 / 拒绝）。
- 纠正事件写入 `feedback_events`，并据此更新 `preferences`（如"含 invoice 的文件归到 工作/报销"）。
- 后续同类文件的建议优先级受 `preferences` 影响。这是"整理习惯"而非"一次性整理"的核心。

### M2 — 虚拟整理层（差异化方向 3）
- 对索引文件打语义标签（如 `工作/合同`、`待报销`、`安装包可删`、`个人/照片`）。
- 提供按标签、按语义搜索的**虚拟视图**，文件物理位置不变。
- 索引基于文件内容指纹（hash + 抽取文本），即使文件被外部重命名/移动，仍能追踪。
- **物理归档是独立动作**：仅当用户显式选择"归档到某目录"时，才进入 M3 的预览-执行流程。

### M3 — 持久化可审计账本 + 条件撤销（差异化方向 4）
- 每次物理操作写入 `operation_log`：`{id, batch_id, source_path, target_path, op_type, suggestion_id, confidence, user_decision, created_at}`。
- 账本 append-only，应用重启后仍可查询与回滚。
- 支持三种撤销：单条撤销、按 `batch_id` 批量撤销、"撤销今天所有由 AI 建议触发的移动"这类条件撤销。
- 撤销本身也作为一条新记录写入账本（不允许物理删除历史记录）。

### M4 — 置信度分层交互（差异化方向 2，作为 M1/M2 的交互实现要求）
- 高置信度（默认 ≥0.8）：进入"建议区"，可一键批量接受。
- 中置信度（0.5–0.8）：进入"待确认区"，需勾选后批量确认。
- 低置信度（<0.5）：进入"待定箱"，不产生移动建议，只展示模型猜测 + 理由，由用户决定。
- 每条建议必须附带**可解释理由**，不能只给百分比。

### M5 — 安全执行器架构（差异化方向 5，作为 M3 的执行层要求）
- 执行器只接受结构化 `OperationPlan`，校验后执行。
- 强制路径 ACL：仅允许在用户授权的根目录内操作；禁止跨盘符；禁止操作系统目录。
- **第一版完全禁用删除能力**。
- 默认 dry-run：生成计划后先展示 diff 预览，用户显式确认才执行。

### M6 — 用户自带 Key 的 Provider 层
- 支持至少 4 个 Provider：OpenAI、DeepSeek、Groq、任意 OpenAI 兼容端点（自定义 Base URL）。
- 每个 Provider 的配置包含：`providerId`、`apiKey`（加密存储）、`baseUrl`（可选）、`model`、`enabled`。
- 设置页有"测试连接"按钮，发起一次最小请求验证 Key 有效性，成功/失败即时反馈。
- Provider 抽象在**主进程侧**实现，对外暴露统一的 `LLMClient.chat()` 接口；渲染层通过 IPC 调用，不知道具体 Provider 细节。

> 本板块列出功能相近的开源项目，供 agent 理解"哪些能力是标配、哪些是 Sift 的差异化"。**不要在实现中照搬任何一个竞品的完整架构**，Sift 的组合是独特的：M1 持续学习 + M2 虚拟层 + M3 跨会话可审计账本三者叠加。

**Sift 的差异化组合**：上述项目中，没有任何一个同时具备 **增量监听 + 用户纠正反馈持续校准 + 虚拟层默认不动文件 + 跨会话可审计账本与条件撤销** 这四件事。FileSense 有置信度但无持续学习；Firefly 有虚拟层但无反馈学习；SlothSort 有账本但偏向自主移动；Backtrack 有安全模型但无增量与学习。**Sift 把这四个能力收敛到一个下载文件夹场景里**，这就是差异化所在。

## 6. 技术架构

### 进程模型与密钥边界
- **Electron 主进程**：窗口管理、服务生命周期、**密钥管理（`safeStorage`）**、**所有 LLM 调用发起方**、文件监听（`chokidar`）、确定性执行器、操作账本写入。
- **Next.js standalone server**：由主进程 `fork` 子进程启动，随机端口 + 启动令牌 + `/health` 就绪轮询后再开窗口。承担 UI 与 API Route。
- **渲染层**：Next.js App Router，启用 `contextIsolation: true` + `sandbox: true`，通过 preload 暴露最小 IPC 面。**渲染层永远不持有、不接收、不缓存 API Key 明文。**
- **Agent / 工具调用**：在主进程或 `utilityProcess` 中执行，不放在渲染层。

### 密钥存储与传递规则（硬性约束）
1. 用户在设置页输入 API Key，渲染层通过 IPC 单向提交明文到主进程，**提交后立即清空输入框**。
2. 主进程收到后调用 `safeStorage.encryptString(apiKey)` 加密，密文写入 `settings` 表（或独立 key 文件），**绝不以明文落盘**。
3. 渲染层查询 Provider 状态时，主进程只返回 `{configured: true, hint: "sk-...xxxx"}`（仅尾 4 位），**永不返回完整 Key**。
4. 所有 LLM 请求由主进程发起（或由主进程派发到 `utilityProcess`），渲染层发起生成请求时只传递业务参数（文件元数据、标签体系、历史反馈），不传 Key。
5. 密钥一旦被用户删除或 Provider 被禁用，主进程立即清除内存中的解密副本。
6. 日志中不允许出现 Key 明文，调试信息需脱敏。

### 技术栈
- Electron + Next.js (App Router) + TypeScript
- SQLite（`better-sqlite3`），WAL 模式，位于 `app.getPath('userData')/sift.db`，首次启动自动建库 + 迁移
- 流式输出：SSE
- 文件监听：`chokidar`
- 内容抽取：PDF / 文本（MVP 先做这两类，图片仅元数据）
- 检索：SQLite FTS5 关键词召回 + 本地 embedding 向量混合（MVP 不引入独立向量库）
- LLM SDK：主进程侧使用官方 SDK 或标准 `fetch`，Provider 抽象为统一接口，支持 OpenAI / DeepSeek / Groq / 自定义 OpenAI 兼容端点

### 关键数据表（最小集合）
```sql
files(id, path, hash, size, mime, extracted_text, indexed_at, status)
tags(id, name)
file_tags(file_id, tag_id, confidence)
suggestions(id, file_id, proposed_tag, confidence, reason, status, created_at)
feedback_events(id, suggestion_id, user_action, from_tag, to_tag, created_at)
preferences(id, pattern, preferred_tag, weight, updated_at)
operation_log(id, batch_id, source_path, target_path, op_type, suggestion_id, confidence, user_decision, created_at)
undo_batches(id, batch_id, undone_at, reason)
settings(key, value)
providers(id, provider_id, base_url, model, encrypted_api_key, enabled, created_at, updated_at)
```

### 关键流程
1. 首次启动 → 选择下载目录 → 只读全量索引 → 建立虚拟视图（**不移动文件**）。
2. 用户可选配置 AI Provider（可跳过）→ 测试连接 → 加密存储 Key。
3. 增量监听 → 新文件 → 抽取内容 → **若已配置 Provider**，打标签并生成带置信度与理由的建议 → 按 M4 分层展示；**若未配置**，文件进入索引与虚拟视图，但不生成建议，UI 提示"配置 AI 后可自动生成建议"。
4. 用户接受/修改/拒绝 → 写 `feedback_events` → 更新 `preferences`。
5. 用户发起物理归档 → 生成 `OperationPlan` → dry-run 预览 → 确认 → 执行器校验 ACL → 执行 → 写 `operation_log`。
6. 撤销 → 读账本 → 反向执行 → 写新记录。

## 7. MVP 范围（必须在本版完成）

- 下载目录授权 + 只读索引（文本 + PDF）
- 增量监听新文件
- **用户自带 Key 的 Provider 配置层**：至少支持 OpenAI / DeepSeek / Groq / 自定义 OpenAI 兼容端点四选一
- **密钥安全边界**：`safeStorage` 加密存储、渲染层零明文、所有调用从主进程发起
- 置信度三档分层 UI + 可解释理由
- 虚拟标签视图 + 语义/关键词搜索
- 纠正反馈写入并影响后续建议（pattern → preferred_tag 权重表）
- 物理归档：dry-run 预览 + 执行 + 写账本
- 单条撤销 + 按 batch 撤销 + 跨会话可用
- 路径 ACL + 禁用删除 + 默认 dry-run
- 未配置 Key 时的优雅降级：核心功能全可用，仅建议生成不可用

## 8. 非目标（本版明确不做）

- ❌ 文件删除
- ❌ 跨盘符操作
- ❌ 云同步 / 账号系统 / 多用户
- ❌ 内置或代理 LLM 额度（不提供免费 Key、不做转发服务）
- ❌ 自动物理移动（自动仅限"进入建议区"）
- ❌ 复杂规则 DSL 或可视化规则编辑器
- ❌ 图片 OCR 内容理解（仅元数据）
- ❌ 多 Agent 编排
- ❌ 移动端

## 9. 验收标准（可量化）

- 首次索引 500 个文件，冷启动到可交互 ≤ 5s（不含索引时间）；索引有进度条。
- 新文件落地到建议出现 ≤ 2s（不含模型调用），模型建议异步补齐。
- **未配置 Key 时，索引 / 虚拟视图 / 手动标签 / 归档 / 账本功能 100% 可用。**
- **渲染层 IPC 面不存在任何返回完整 API Key 的接口；抓取渲染层内存或日志，均无法还原 Key 明文。**
- 物理归档 dry-run 预览 100% 覆盖每个路径变更。
- 任意一次归档操作可在应用重启后通过账本完整撤销。
- 低置信度文件 100% 进入待定箱，不产生自动建议移动。
- 账本记录可导出为 JSON。

## 11. 用户故事（User Walkthrough）

> 描述用户从安装到日常使用的完整操作路径。每一步写清：**用户做什么动作 → 界面出现什么 → 系统在背后做了什么**。Agent 应据此设计页面路由与交互，而不是凭空造 UI。

### 11.1 首次启动（Onboarding，约 60 秒）

1. 用户双击打开 Sift。窗口出现，显示欢迎页，一句话说明产品定位：「帮你看清下载文件夹，默认不动你的文件。」
2. 页面中央一个按钮「选择要整理的文件夹」。用户点击 → 系统弹出原生目录选择框。
3. 用户选中「下载」文件夹，确认。界面立即显示一行提示：「正在只读扫描，不会移动任何文件。」下方出现进度条（已索引 N / 总数 M）。
4. 扫描期间，右侧逐步出现文件卡片，按语义标签分组（`工作/合同`、`待报销`、`安装包可删`、`个人/出行`、`待定`）。**文件物理位置不变。**
5. 扫描完成，进入 **可选步骤「配置 AI」**：
   - 页面说明：「Sift 需要你自备一个 AI Provider 的 API Key 才能自动生成分类建议。也可以先跳过，之后在设置里配置。」
   - 提供 Provider 下拉（OpenAI / DeepSeek / Groq / 自定义 OpenAI 兼容端点）、API Key 输入框（密码掩码）、可选 Base URL、模型名。
   - 有「测试连接」按钮，点击后主进程发起一次最小请求，成功显示「连接成功」，失败显示错误原因。
   - 有「先跳过」按钮，点击直接进入主界面。
6. 若跳过配置，主界面顶部显示一条**可关闭的提示条**：「未配置 AI，自动建议已关闭。点击配置。」
7. 首次引导结束。用户此时不需要做任何确认动作，可以直接关闭窗口。

**关键约束**：
- 整个 Onboarding 过程中，磁盘上零文件变更。
- API Key 输入框在提交后立即清空，只保留「已配置 · sk-...xxxx」状态显示。
- 跳过配置不影响任何离线功能。

### 11.2 日常使用（应用常驻后台）

1. 用户正常用浏览器下载文件。Sift 常驻系统托盘，不弹窗打扰。
2. 新文件落地后 ≤2 秒：
   - **已配置 AI**：托盘图标出现小红点表示「有 N 条新建议」；主进程异步调用用户配置的 Provider 生成建议。
   - **未配置 AI**：文件进入索引与虚拟视图，托盘无红点，UI 中该文件标记为「待归类」，需用户手动打标签。
3. 用户点击托盘图标 → 窗口弹出，直接落在「建议区」（若未配置 AI，落在「虚拟视图」）。
4. **建议区**：每条建议是一张卡片，包含文件名、建议标签、置信度、一句理由。
   - 高置信度卡片默认勾选，顶部有「全部接受」按钮。用户点一下 → 文件被打上标签、进入虚拟视图，**文件仍在原地**。
   - 中置信度卡片不默认勾选，用户逐条勾选后点「接受所选」。
5. **待定箱**：低置信度文件不出现「接受」按钮，只有「指定标签」下拉和「忽略」两个操作。用户必须主动决策。
6. 用户如果觉得某条建议错了，卡片上有「改到…」下拉，选一个新标签后点确认。这次纠正被记录，下次同类文件进来时，建议直接落到用户改过的标签。
7. 用户随时可以在顶部搜索框输入自然语言，结果来自虚拟索引，点击结果直接用系统默认程序打开文件——**不移动文件**。

### 11.3 物理归档（用户显式发起的动作）

1. 用户在虚拟视图里按标签筛出 `待报销`，看到 11 个文件。
2. 用户框选或全选，点击顶部「归档到…」按钮。
3. 弹出目标目录选择框，用户选一个「财务/报销」文件夹。
4. 界面切换到 **dry-run 预览页**：11 条路径变更逐条列出，其中 2 条标黄并附提示「置信度较低，请确认」。
5. 用户取消勾选那 2 条标黄项，点「确认执行」。
6. 系统执行移动，显示「已完成 9 项，已写入操作账本」。提供「查看账本」「撤销本次」。
7. 用户点「查看账本」→ 跳到账本页。用户点「撤销本次」→ 9 个文件全部回到原路径，撤销行为作为新记录写入账本。

**关键约束**：没有 dry-run 预览，执行按钮不可用。执行器在后台校验路径 ACL，任何越界或删除请求整批拒绝。

### 11.4 复盘与撤销（随时可用）

1. 用户从侧边栏进入「操作账本」页。
2. 页面按时间倒序列出所有物理操作，可按日期、批次、标签筛选。
3. 每条记录可展开，看到：源路径、目标路径、触发它的建议、置信度、用户当时的选择。
4. 单条记录右侧有「撤销」按钮；批次头部有「撤销整批」按钮。
5. 用户点撤销 → 确认弹窗 → 执行反向操作 → 账本新增一条撤销记录。原记录保留，不可删除。
6. 页面右上角有「导出账本」按钮，导出 JSON。

### 11.5 设置页（最小集）

- **下载目录**：可更换授权目录（更换后重建索引，旧账本保留）。
- **置信度阈值**：高/中两档阈值可调（默认 0.8 / 0.5）。
- **AI Provider**：
  - Provider 下拉：OpenAI / DeepSeek / Groq / 自定义 OpenAI 兼容端点。
  - API Key 输入框（密码掩码）。已配置时显示「已配置 · sk-...xxxx」，提供「更新」「移除」按钮。
  - 自定义端点时显示 Base URL 输入框。
  - 模型名输入框（带各 Provider 的常用模型占位提示）。
  - 「测试连接」按钮，即时反馈成功或失败原因。
  - 说明文字：「API Key 经加密后存储于本机，所有请求由应用主进程直接发往你选择的 Provider，Sift 不做任何中转。」
- **隐私说明**：静态文字，说明哪些数据本地存储、哪些会发给 Provider、Key 的加密与存储方式。
- **开机自启开关、托盘常驻开关**。

### 11.7 一次典型使用的时间线

## 12. 建议实现顺序

1. Electron + Next.js standalone 骨架跑通，health check + 窗口打开。
2. SQLite 自动建库 + 迁移 + 表结构。
3. 目录授权 + 只读索引 + 虚拟视图（先不做 AI）。
4. **Provider 配置层 + `safeStorage` 加密 + 主进程调用 + IPC 边界**（先只做 OpenAI 兼容一种）。
5. 接 Provider 生成标签与建议（先只做高/低两档）。
6. 补中置信度与理由展示。
7. 实现执行器 + dry-run + 账本 + 撤销。
8. 补纠正反馈学习（preferences 权重）。
9. 补指标测量与 README/演示录屏。

**每一步都要可运行、可演示，不要并行铺开多个未完成模块。**
