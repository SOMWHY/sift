# Sift MVP 演示录屏脚本（Demo Script）

> 目标：在 ~3 分钟内展示 Sift 的核心价值 —— 默认不动文件、置信度分层、纠正反馈学习、dry-run 归档、跨会话撤销、密钥安全边界。
> 录制前准备：干净用户数据目录（可设置 `--user-data-dir` 或删除 dev userData）、一个含 15–20 个混合文件的演示「下载」文件夹（PDF 发票、合同、照片、安装包、纯文本等）。

---

## 场景 0：冷启动与首次授权（0:00–0:30）

1. 双击启动 Sift，窗口打开，落在欢迎页「帮你看清下载文件夹，默认不动你的文件。」
2. 点击「选择目录」，弹出原生目录选择框，选中演示下载文件夹。
3. 页面显示「已授权目录：<path>」，后台开始只读索引（进度条）。
4. 口播：「第一步只做只读扫描，不移动任何文件。」

**展示点**：只读索引 + 进度条；冷启动到可交互的响应速度。

---

## 场景 1：无 AI Key 的优雅降级（0:30–0:50）

1. 此时尚未配置 Provider，页面顶部显示可关闭提示条「未配置 AI，自动建议已关闭。」
2. 进入 `/library` 虚拟视图：文件已按标签分组、可搜索、可手动打标签。
3. 口播：「没有 API Key，索引、虚拟视图、手动标签全部可用 —— AI 是增强层，不是单点依赖。」

**展示点**：未配置 Key 时核心功能 100% 可用。

---

## 场景 2：配置 Provider 与测试连接（0:50–1:20）

1. 进入 `/settings` → AI Provider。
2. 下拉选择 Provider（如 DeepSeek），填入 API Key（密码掩码）。
3. 点「测试连接」→ 显示「连接成功」。
4. 展示状态变为「已配置 · sk-...xxxx」，并强调：**渲染层拿不到完整 Key，所有调用由主进程发起**。

**展示点**：密钥安全边界（仅尾 4 位 + 主进程发起调用）。

---

## 场景 3：增量监听 + 置信度分层（1:20–2:00）

1. 用文件管理器往演示下载文件夹丢入 3 个新文件（一个 `invoice_2026Q3.pdf`、一个模糊命名的文件、一个低置信度文件）。
2. ≤2 秒内托盘出现红点，窗口落在 `/inbox` 建议区。
3. `/inbox`：高置信度卡片（如「待报销 · 0.91 · 文件名含 invoice」）默认勾选，点「全部接受」。
4. `/to-confirm`：中置信度卡片需勾选后批量确认。
5. `/pending`：低置信度卡片只有「指定标签」和「忽略」，**不产生移动建议**。

**展示点**：增量监听 ≤2s（不含模型调用）；三档分层；每条建议带理由。

---

## 场景 4：纠正反馈学习（2:00–2:25）

1. 在 `/inbox` 对某条建议点「改到…」，选一个新标签（如 `工作/报销`）。
2. 口播：「这次纠正已被记录，下次同类文件进来，建议会直接落到你改过的标签。」
3. （可选）再丢一个同 pattern 文件，展示建议标签已被纠正。

**展示点**：`feedback_events` + `preferences` 权重影响后续建议。

---

## 场景 5：dry-run 归档 + 账本 + 撤销（2:25–3:00）

1. 进入 `/library`，筛出 `待报销` 标签，全选，点「归档到…」，选目标目录。
2. 进入 `/archive/preview`：逐条路径变更预览，低置信度项标黄，取消勾选。
3. 点「确认执行」→ 显示「已完成 9 项，已写入操作账本」。
4. 进入 `/ledger`：时间线展示源路径/目标路径/触发建议/置信度/用户决策。
5. 点「撤销本次」→ 文件回到原路径，账本新增一条撤销记录。
6. 点「导出账本」→ 下载 JSON。

**展示点**：dry-run 全覆盖；append-only 账本；跨会话可撤销；可导出 JSON。

---

## 收尾

口播总结：「Sift = 默认不动文件 + 持续学习整理习惯 + 可审计可撤销。所有索引、账本都留在本机，密钥由你自备、主进程加密存储。」
